The release must meet `REWRITE_PLAN.md` R0 to R8 and the remaining data, power, compatibility and release rules in `ENGINEERING_PLAN.md`. The rewrite plan replaces the older migration sequence, not those gates.

Update a row's status when its work lands and attach the commit, test result, measurement or decision that meets its done check. Rows start as open, in progress or blocked. Mark them done only after the check passes. A decision that includes a feature also includes its implementation and tests. An exclusion must be explicit and owner-approved. Keep the IDs stable when adding rows.

Document source paths below are relative to `docs/kaia/`; code and tool paths are relative to the repository root. The five named work items remain in progress, including finished ink on the unmerged `kaia/ink` branch. Code inspection is not a passing test or a device measurement.

Kobo services excluded by `nickel/PARITY.md` section 3, its Q38 and Q49 to Q55, and the explicitly unplanned games, sketch pad and web browser are outside completion. Ambient light and recognition need the explicit scope decisions below. Built tier items remain covered by the regression and device checks rather than new implementation rows.
