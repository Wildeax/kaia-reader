## Rust crates

Generated by `tools/kaia/inventory/rust_licenses.py`. Do not edit by hand. Rerun the script.

Regenerate from the repository root. Source `tools/kaia/env.sh` first so that `cargo` is on `PATH`.

```sh
python3 -I tools/kaia/inventory/rust_licenses.py --root .
```

The script runs `cargo metadata` and `cargo tree` in `rust/` with `--locked`, so `rust/Cargo.lock` does not change. It rewrites only this section.

Scope:

- `kaia (desktop)` is the `kaia` binary with default features. `kaia (kobo)` is the same binary built with `--no-default-features --features kobo`. `libkaia.so` is `kaia-ffi` with default features, plus `--features glibc215` for the Kobo build. The Used by column lists every build that links the crate.
- Normal dependencies for every target (`--target all`), so the rows cover more than the release builds. The release builds are macOS (`aarch64-apple-darwin`), Linux (`x86_64-unknown-linux-gnu`) and Kobo (`armv7-unknown-linux-gnueabihf`). A row that no release build compiles says so in the Note column.
- Dev dependencies are left out. Build tools such as `cc`, `cmake` and `bindgen` run at build time and do not link into the product, so they have no rows. Native code that a build script compiles into the product is named in the Note column. Proc macros also run at compile time. They stay in the table, because cargo lists them as normal dependencies, and the Note column marks them.
- Workspace crates have no rows. They carry the repository license. The workspace `-sys` crates (`kaia-mupdf-sys`, `kaia-cre-sys`, `kaia-djvu-sys`, `kaia-fbink-sys`) link native libraries that KOReader builds from `base/thirdparty`. Those licenses are in the Native dependencies section above.
- The License column is the expression each crate declares in its `Cargo.toml`. The script does not read the license text.

### What the release must ship

- Ship the license files of every crate in the table. Copy every license file the crate has, not only the one its expression names. `ring` has three.
- Ship every NOTICE file under its original name. Apache-2.0 requires it in redistributions.
- For a crate whose package has no license file, copy its license text from the repository named in the Note, and check that the copy matches the declared license.
- Where an expression offers several licenses, the release records the one it uses. The Note lists the choices that `rust/deny.toml` allows.
- `docs/kaia/RELEASE_SOURCE_CHECKLIST.md`, section 9, tracks these steps.
