# Bundled plugin inventory

Baseline: Upstream KOReader v2026.07.1 (9192014d8), plus Kaia example and stickers plugins. Current plugin tree scanned on 2026-10-13. Generated by `tools/kaia/inventory/plugin_inventory.py`. Do not edit by hand; edit `tools/kaia/inventory/curation.json` and rerun the script.

## Method and limits

This inventory comes from a static text scan of every `.lua` file in each `plugins/*.koplugin` directory. The scan blanks Lua comments and string contents, then counts `require` targets, UI registration calls, device checks, file and network access, document calls and settings writes. Names and descriptions come from each `_meta.lua`. Platform applicability, compatibility classes and workflows come from reading each `main.lua` and the Kobo Libra Colour capability flags in `frontend/device/kobo/device.lua`. The scan cannot see dynamic Lua behavior. It misses requires built from variables, calls made through tables, code loaded by other plugins and anything that changes at runtime. Runtime tracing (KR-012) covers those cases. Treat counts as leads for review, not as proof that code is absent. The raw counts and call sites are in `plugins.json`.

## Compatibility classes

Compatibility classes use these rules. Not applicable on Kobo means the plugin disables itself on Libra Colour or is a developer template. Custom-drawing or deeply coupled means the plugin draws with Blitbuffer, patches a core class or writes core state at run time. Applicable bundled plugin means the plugin uses no dialogs or lists beyond the standard container and single message or confirm dialogs. Plugin using shared widgets covers every other applicable plugin.

## Loader and gating

The loader (`frontend/pluginloader.lua`) loads every `*.koplugin` directory in `plugins/` and in `extra_plugin_paths`. No plugin is disabled by default in the loader. Three things turn a plugin off. A user can add its name to the `plugins_disabled` setting, and the plugin then appears in the plugin manager without running `main.lua`. A user can set `plugins_disable_external`, which turns off every plugin not in `BUILTIN_PLUGINS`. And `main.lua` can return `{ disabled = true }`, which makes the loader skip the plugin without an error.
