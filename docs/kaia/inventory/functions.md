# User-visible functions at the baseline

Baseline: the plugin and frontend tree at b5ad80933. The reader modules and the plugins are unchanged from upstream KOReader v2026.07.1 (9192014d8). In `filemanager.lua`, the title now reads the product name from `kaia/identity`. `common_info_menu_table.lua` also differs from upstream, and it is not a module listed here.

## Method and limits

The module list is every `.lua` file in `frontend/apps/reader/modules/` (37 files) and `frontend/apps/filemanager/` (10 files). The `filemanager/lib/` directory holds `md.lua`, a Markdown helper with no menu, so it is not listed.

Data columns come from a grep of settings writes: `saveSetting`, `flipNilOrFalse`, `makeTrue`, `makeFalse`, `delSetting`, and `doc_settings` table writes. Keys marked "built at run time" come from code that builds the key from a variable, so a grep cannot name them. Workflows and the menu wording come from reading each module header and its menu labels. The grep misses writes made by other modules on the module's behalf, so treat the data column as a floor, not a complete list.

The compatibility class says how far an external plugin can depend on a module's internals. "Custom-drawing or deeply coupled" means the module paints the page, changes document rendering, or owns core state that plugins touch. "Plugin using shared widgets" means the module builds dialogs and menus from shared widgets. "Not applicable on Kobo" means the module gates itself off on Kobo Libra Colour. No core module is an "Applicable bundled plugin", because that class applies to plugins only. Runtime tracing (KR-012) checks the events and state these modules actually touch.
