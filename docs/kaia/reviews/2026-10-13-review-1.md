# Review 1 findings (2026-10-13)

Independent review of the Rust crates by stronger-model reviewers, before the first Kobo build of the Rust app. Each finding has a fix status.

## Gestures and input (kaia-input, kaia-app, kaia-lua)

| ID | Severity | Finding | Status |
|---|---|---|---|
| G-H1 | High | App clock mixes scheduler time (from app start) with kernel event timestamps, so on a Kobo hold fires only at lift (`kaia-app/src/app.rs` "now" = max(scheduler.now, last_input)). | Open |
| G-H2 | High | Lua `ges` tables: multiswipe directions as array not string; pinch/spread/inward/outward axis in `axis` not `direction`; rotate `turn` not `direction`; `relative` missing on pans. | Sent to Lua L2 worker |
| G-M1 | Medium | Detector treats each touch sample as a frame; KOReader updates all slots per frame first. Rotate lost, two-finger pan values differ. Needs frame batching from the evdev decoder (SYN_REPORT) into the detector. | Open |
| G-L1 | Low | Two-finger midpoints round down; KOReader rounds half up. | Open |
| G-L2 | Low | hold_pan from inward or outward pan drops direction, span, start_span, end_pos. | Open |
| G-L3 | Low | No runtime setter for disable_double_tap and tap_interval_override (KOReader changes them per window, for example the keyboard). | Open |

## Data durability (kaia-library, kaia-book, kaia-events, Lua app)

| ID | Severity | Finding | Status |
|---|---|---|---|
| D-C1 | Critical | An empty or unmounted library root counts as a complete walk, so every book under it is removed with its collections and history (cascade). Reproduced. | Open |
| D-C2 | Critical | A case-only rename on a case-insensitive volume (Kobo FAT, macOS APFS) loses collections, history, status and progress: exact path compare plus "old path still exists". Reproduced. | Open |
| D-H3 | High | Per-book state is keyed only by partial MD5, so any edit to the book file (Calibre metadata update) detaches position, highlights and notes. | Open |
| D-H4 | High | Reading state is saved only when the reader closes; a dead battery or crash loses everything since opening. | Open |
| D-H5 | High | Two sessions on one book: last writer wins, and both write the same .tmp file. Reproduced. | Open |
| D-H6 | High | A state file from a newer Kaia is renamed to .unreadable and replaced after a rollback; contradicts STORAGE.md. Reproduced. | Open |
| D-H7 | High | Lua app (shipped): DocSettings.updateLocation, file manager rename and move, "Move book metadata", Reset, and the unparsable-candidate delete in DocSettings:open still delete stock KOReader's book-folder sidecar. | Open, urgent |
| D-M8 | Medium | A non-UTF-8 byte in a KOReader sidecar makes Kaia import the older .old backup silently; library imports fail outright. Reproduced. | Open |
| D-M9 | Medium | Lua import copies KOReader SQLite databases without their -wal files. | Open |
| D-M10 | Medium | Opening a book with a KOReader sidecar fails entirely when the disk is full (save after import uses ?). | Open |
| D-L1 | Low | .old backup refreshed only when older than 60 s; during active reading there may be no backup. | Open |
| D-L2 | Low | File-change flag reported once, then lost. | Open |
| D-L3 | Low | Covers dropped in the PNG to JPEG migration never come back (book stays extracted). | Open |
| D-L4 | Low | FAT local-time mtimes may make every book look changed after a time zone or DST change (uncertain). | Open |
| D-L5 | Low | kaia-storage gc deletes an asset added for a sticker that is not saved yet. | Open |
